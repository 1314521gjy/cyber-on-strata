# 05 · 速度账：逐项拆分、命中率、噪声底

> 本文把流式档的每 token 时间拆开、给出命中率构成与实测区间，并写清"哪些差值不可判"。
> 证据等级：`A` 本机自实测 ｜ `B` 同机对照实现 ｜ `C` 外部实测 ｜ `D` 推导或出处自报。

## §1 先看总量

| 档 | decode | 生效缓存 | CPU 专家池 |
|---|---|---|---|
| **流式（验收档，reserve 24568）** | **57.68 / 58.60 / 61.56 / 61.83 / 63.48 tok/s** | 2348 slots / 4.20 GiB | 1.54 个专家/层，5.42–5.98 ms/token，20.5–22.5 GB/s |
| 专家全常驻（reserve 1500） | **134.18 / 136.02 tok/s** | 10240 slots / 18.32 GiB | **完全不工作**（`0.000 ms/token`、`0 dispatches`、`0.00 专家/层`） |

prefill：**1736–2203 tok/s**；TTFT ≈ **1.8–1.9 s** @2002 tokens。

## §2 逐项拆分

### 2.1 三大块

| 项 | 读数 | 占比 |
|---|---|---|
| **GPU 地板**（`wait for rings`） | **6.387–6.392 ms** | — |
| └ GPU 纯计算 | **5.79 ms** | — |
| └ 门铃握手 | **0.80 ms**（0.797 ms/轮按 40 层摊开 ⇒ 每层真实 GPU 计算 **144.8 µs**） | — |
| **CPU 专家池**（`pool`） | **3.168–3.283 ms** | — |
| **staging / 杂项**（embed + head + sample + host/commit） | **1.814 ms** | — |
| **合计 `per token`** | **11.390 / 11.462 / 11.427 ms** | ⇒ **87.2–87.8 tok/s 等效** |

**自证（表的和必须对上引擎自己的计数器）**：

| 仪器侧 | 引擎自报 | 判 |
|---|---|---|
| 层均值自旋求和 = **6.590 ms/轮** | `wait for rings` **6.590** | ✅ |
| 层均值池求和 = **3.086 ms/轮** | `pool` **3.088** | ✅ |

⇒ **仪器测的就是它宣称的东西**（这是"读数可信"的前提，不是可选项）。

### 2.2 流式开销的构成（关键一条）

无流式上限 **6.894 ms/token ⇒ 145.5 tok/s**。

| 账 | 计算 |
|---|---|
| **流式开销（干净的差）** | `11.427 − 6.894 =` **4.533 ms/轮** |
| └ CPU 专家池 | **3.226 ms（71%）** |
| └ **GPU 自己变慢** | **1.307 ms（29%）** |

⚠️ **第 29% 那项是最有价值的反直觉发现**：流式档 GPU 要算的专家**更少**（6.56 vs 7.5 个/层）**却更慢**。
嫌疑机制 = **未命中专家的 DMA 占用 GPU 时间线**（1199 blob / 32 轮 ≈ 37.5 个/轮 ≈ **71 MB/轮**，
PCIe 24 GB/s ⇒ ~3 ms 的 DMA 必须落在那条线上）。**⇒ 这是流式开销里唯一还没被证明"到头"的一项。**

⇒ **现状 = 上限的 60%**（87.4 / 145.5）。

### 2.3 为什么搬这么多字节：573 MB/token 的账

| 步 | 计算 | 读数 |
|---|---|---|
| 每专家参数 | `(2048×512)×2 + 512×2048` | **3,145,728** |
| 专家总参数 | `40 × 256 × 3.145728e6` | **32.2 B** |
| Q4_K_XL（≈4.5 bit）⇒ 总字节 | `32.2e9 × 4.5 / 8` | **≈18.1 GiB** |
| **引擎自报的 arena** | 日志 `loaded 18.32 GiB at 3.65 GiB/s` | **18.32 GiB** ✅ 吻合 |
| 每专家字节 | `3.145728e6 × 4.5 / 8` | **≈1.79 MB** |
| 每 token 专家激活 | `40 层 × top-8` | **320 个** |
| **每 token 专家字节** | `320 × 1.79 MB` | **≈573 MB** |

**两条独立路径收敛到同一带宽**：

| 跑 | 窗口 | 每层 CPU 专家 | 每轮字节 | 池耗时 | 推出带宽 | 日志自报带宽 |
|---|---|---|---|---|---|---|
| s21 | 4 | `4.90 routed` | `4.90×40×1.79MB` = 351 MB | 28.072 ms | **12.5 GB/s** | **11.2 GB/s** ✅ |
| s22 | 2 | `2.60 routed` | `2.60×40×1.79MB` = 186 MB | 20.180 ms | **9.2 GB/s** | **10.0 GB/s** ✅ |

⇒ `573 MB ÷ 10–13.6 GB/s = 34–46 ms/token ⇒ 22–29 tok/s`，与当时实测 **29.21 tok/s** 吻合。

### 2.4 上界对照

| 臂 | 专家缓存 | decode | 等效带宽 |
|---|---|---|---|
| 10240 槽 = 全部专家常驻 | 21.95 GiB | **212.77 tok/s**（4.7 ms/token） | GPU 侧 **≈122 GB/s** |
| 1963 槽 | 4.21 GiB | **29.21 tok/s** | 主机侧 **10–13.6 GB/s** |
| 差 | | **7.3×** | **≈10×** |

⇒ 差额**全部来自"主机侧搬字节"**。

⚠️ **跨批提醒**：上表两臂与 §1 的 57.68–63.48 / 134.18–136.02 **不是同一批** ⇒ 数值不可直比。
可判的只有方向（两批一致）。**变红条件**：若出现"流式 ≥ 全常驻"的任一例 ⇒ 该方向不成立。

## §3 命中率

### 3.1 构成

| 项 | 读数 |
|---|---|
| 命中率（`R4 expert-cache hits`） | **0.7794**（6948 / 8915），`0 admitted, 1967 refused, cache 100.0000% full` |
| CPU 专家池 | **1.54 distinct / 1.54 routed 每层** |
| prompt 借槽 | `812 lent slots refilled in 69.2 ms` |
| **缓存永不收人** | `0 admitted / cache 100% full` |

⇒ **命中率 100% 由 profile 排名 × 槽数决定**。槽数不够时，**换 profile 比调别的东西都有效**。
（同批证据：旧 profile 0.6372 / CPU 2.35 每层 → 新 profile 0.7881 / CPU 1.61；两配置 `slots` **逐字相同 1963** ⇒ 排除"偷槽"。）

### 3.2 不能反推的东西

- **`routed/layer` 不能反推命中率**：实测出现过 `routed/layer 0.94` 与命中率 87.52% 的组合，也出现过 1.29；
  关系被自适应层的 `swaps` 扰动（T8=239 / T5=330 / T10b=313 / T12=349）。
- **引擎的槽位分配不只是"ranking 的前 N 个"**。

### 3.3 一条被证伪的机制假设（**保留为资产**）

| 假设 | 判据 | 结果 |
|---|---|---|
| "trace 文件越多 ⇒ 聚合频次分布越平 ⇒ 排序区分度下降 ⇒ 更差" | 用**留出集覆盖率**检验（不在任何 trace 里的那批路由），要求 Spearman ρ ≤ −0.6 | 覆盖率从 T3 起几乎完全平坦（0.7884–0.7956），而 `routed/layer` 变化 1.03–1.29；覆盖率**最高**的 T12（0.7956）**恰恰实测最差**（1.29）；**ρ = −0.314** ⇒ **预测失败，机制不成立** |

## §4 噪声底（**本节决定别的数字能不能判**）

### 4.1 噪声底

| 项 | 读数 |
|---|---|
| 同配置**同批**散布（decode） | **≥ 5.75 tok/s** |
| 同配置同批散布（`pool` ms） | **2.49 ms** |
| 旧口径记录值 | 4.13 tok/s |
| 一批 6 条同配置读数 | decode = 43.15…63.48（散布 **20.33**）；`pool` = 5.422, 5.808, 5.978, 6.349, 7.057, 7.912（散布 2.49） |
| **跨批漂移** | **15–20%** |

**⇒ 两条硬规则**：① 速度结论必须**同批交错**（ABBA / 拉丁方）、**首轮丢弃**、n ≥ 2 配对；
② **任何 ≤ 6 tok/s 的效应一律不可判**。

### 4.2 "切换配置后第一条臂被污染"的教训

| 项 | 读数 |
|---|---|
| 同配置、相邻两条臂 | **43.15 vs 63.48 tok/s** |
| 池带宽 | **11.4 vs 22.5 GB/s** |
| 方向 | 切换配置后的**第一条**运行**慢** |

⇒ **报数请跑第二条**。

### 4.3 一条"效应存在但小于噪声"的实例（NO SIGNAL 的正确写法）

`--pool-workers 6` vs `4`，同批交错、丢首次：w6 = 44.35..50.10（mean 47.85, n=3）；
w4 = 46.59..49.84（mean 48.85, n=4）；gap = **−3.51**，**区间重叠**；同配置自身散布 **5.75 > 记录噪声底 4.13**
⇒ **判 NO SIGNAL**，旧"6 最优"**作废**。
⚠️ **不许写成"6 不好"** —— 只能说"这个样本量判不出来"。

### 4.4 一条"效应太小"的实例

`--pcie-frac` 四点扫描（同批 ABBA）：

| `--pcie-frac` | decode | `wait` | `pool` | CPU 专家/层 | PCIe 分流 |
|---|---|---|---|---|---|
| 0.55（引擎原生包默认） | 24.68 | 11.806 | 23.973 | 2.60 | 141/256 |
| 0.00（负控：全给 CPU 池） | 28.97 | 5.785 | 24.763 | 4.82 | 0/256 |
| 0.85 | 29.89 | 19.467 | 9.916 | 1.17 | 218/256 |
| 1.00 | 36.00 | 23.883 | **0.047** | **0.00** | **256/256** |

**事先写下的判据**是"`decode` 随 `pcie_frac` 单调上升，**且 `--pcie-frac 0` 是最慢点**"。
实测 **`0.00` = 28.97 > `0.55` = 24.68** ⇒ **"0 是最慢点"不成立，曲线也不单调**（0.55 是局部最小）
⇒ **用来解释它的机制（"PCIe 比 CPU 池快 2.4 倍，所以多走 PCIe 该更快"）被自己的数据推翻**。
讽刺的是：**引擎原生包默认值 0.55 恰好落在四个点里最差的位置**。

## §5 出处

**测量环境**：本机 = RTX 4080 SUPER + i7-13790F + 96 GiB DDR4-2667；除注明外均为 `A` 级自实测。

| 结论 | 证据 |
|---|---|
| 流式档 decode / prefill / 命中率 / CPU 池 | 本机 `decode` / `prefill` / `R4 expert-cache hits` / `the CPU expert pool` 自报行 |
| 常驻档 134.18 / 136.02 / 10240 槽 / `pool 0.000` | 本机 ABBA 同批交错臂 |
| GPU 地板 6.387–6.392、`pool` 3.168–3.283、杂项 1.814、`per token` 11.390–11.462 | 本机 `verify window` / `wait for rings` / `pool` / `per token` 自报行 |
| 仪器自证：层均值求和对上引擎计数器（6.590 / 3.088） | 三件独立仪器与引擎计数器互校 |
| 流式开销 4.533 = `pool` 3.226 + GPU 变慢 1.307；无流式上限 6.894 / 145.5 | 同配置有 / 无流式两档的干净差 |
| 573 MB/token 的账、两条独立路径收敛到同一带宽 | §2.3 的表 × 两条实测臂的耗时与自报带宽交叉验证 |
| 上界对照 212.77 / 29.21 | §2.4 的两档臂 |
| 命中率 0.7794 逐字行、借槽 812 | 本机引擎自报行 |
| 旧 / 新 profile 命中率与 CPU 专家、`slots` 逐字相同 | 本机同批交错 8 臂 |
| `routed/layer` 不能反推命中率、自适应层 `swaps` 扰动 | 本机引擎 `swaps` 与 `routed/layer` 的同向观察 |
| U7 机制被证伪（Spearman ρ = −0.314） | 留出集覆盖率离线复算 |
| 噪声底 5.75 / 2.49 / 20.33、跨批 15–20%、ABBA 4.13 | 本机同批交错读数的散布统计 |
| 污染臂 43.15 vs 63.48、池带宽 11.4 vs 22.5 | 同一批内相邻两条臂的差值 |
| `--pool-workers` NO SIGNAL 与"6 最优"作废 | 同批交错配对比较（区间重叠，§4.3） |
| `--pcie-frac` 四点与判据被推翻 | 本机四点扫描（含 `0.00` 负控，§4.4） |
