# 04 · 正确性口径

> 本文定义"怎么判这个引擎算得对"，并登记已修的两处数值缺陷及其判据。
> 证据等级：`A` 本机自实测 ｜ `B` 同机对照实现 ｜ `C` 外部实测 ｜ `D` 推导或出处自报。

---

## §1 为什么不能用自我参照做正确性锚

**自我参照（参考串由待测 exe 自己产出）只能判"稳"，不能判"对"。**
唯一有效的锚是**外部 llama.cpp** 在**同一串 token id**、**同一份 GGUF**、**贪心**下产出的串。

| 项 | 值 |
|---|---|
| 参考实现 | `llama-server.exe`，`version: 0.3.0-dev (build 10786, commit de8656bd9)`，Clang 20.1.8 / Windows x86_64 |
| 服务旗标 | `-m <GGUF> --host 127.0.0.1 --port 8093 -ngl 99 -c 4096 --temp 0 --seed 1 --parallel 1 --no-webui -lv 4` |
| 口径 | `temperature=0`（贪心）、`n_predict=32`、`seed=1`、`cache_prompt=false`、`spec_type=none`（**不带 MTP**）、`flash_attn=false`、`ctx=4096`、`ngl=99` |
| prompt | 2003 个 token id，range 1..210126，`sha256(ids) = d3ff937704bde8b79b18a3235a4988075eca8522eb5bc4179e3075a632f62c3f` |
| 参考串（32 个 id） | `514 21 19 516 6000 11 514 21 19 516 9167 11 715 9 4129 1174 198 320 24033 43414 76946 50 24033 43414 198 320 198 320 561 61369 513 5158` |

## §2 逐位对照的方法

### 2.1 先证参考侧产物是真品

**没这一步，后面所有对照都是空转。** 参考臂 10 条断言全 PASS、退出码 0：

| # | 断言 | 读数 |
|---|---|---|
| A1 | 喂的 id 在脚本内解析正确 | 2003 个整数，range 1..210126，全在 vocab [0,248320) 内 |
| A2 | **服务端实际评估的 token 数** | `tokens_evaluated = 2003`、`timings.prompt_n = 2003` |
| A3 | 没有吃 prompt 缓存（吃了 = 没真预填充） | `timings.cache_n = 0` |
| A4 | 喂的 id → `detokenize` → `tokenize` 回来**逐位相同** | 2003 个，`first_diff = -1` |
| A5 | **服务端自己回显的 prompt** 与 `detokenize(喂的 id)` **逐字节相同** | 两侧均 **6000 字符**，byte-equal = True |
| A6 | `tokenize(resp.prompt)` 与喂的 2003 个 id 逐位相同 | 2003 个，`first_diff = -1` |
| A7 / A8 | 生成数量 32、口径 `temperature=0.0` / `n_predict=32` | PASS |
| A9 / A9b | **模型身份由服务端自报**：`/props` 的 `model_path` 与 `-m` 逐字符相等；停机后日志含 `loading model '<全路径>'` | PASS |

**三条独立交叉校验**：生成 id 同时取两条路（`return_tokens: true` 与 `n_probs: 1`），
**两条路逐位相等**（不等则脚本 exit 8 拒跑）。

### 2.2 负控（判据必须有牙）

把比对基线的第 1999 个 id 扰动 1 个 token：

| 项 | 读数 |
|---|---|
| A4 / A6 | **FAIL**，`first difference at index 1999` ← **正好是注入点** |
| 产物 | 写成 `…-INVALID.json`（**未**覆盖有效产物） |
| 退出码 | **7**（如预期拒绝） |

⚠️ **诚实登记**：负控只覆盖 A4 / A6。**A5 在负控里保持绿**，这是构造使然而非缺陷 —— 负控扰动的是 A4/A6
用的比对基线，没走 A5 那条路。**A5 未被负控覆盖 = 未验**。

### 2.3 判定"首个分岔"

把引擎的 `output :` 串与参考串逐位比，第一个不等的下标即**首个分岔**。
判据：**分岔越靠后越好**；同一配置多次跑 `output :` 必须**逐字节相同**，否则读数作废。

## §3 近并列翻转的判别法（**核心口径**）

### 3.1 仪器

| 路径 | 产出 |
|---|---|
| `n_probs=10` | `completion_probabilities[].top_logprobs[] = {id, token, logprob=ln(p)}`，`p` 是**全词表 softmax over PRE-sampling logits** |
| `return_tokens: true` | 整串生成的 id |

因 `p` 来自全词表 softmax 的 logits ⇒ **logprob 之差就是 logit 之差**。

### 3.2 判定规则（**事先写死**）

`k = 10`；`Δlogit = logprob(参考 argmax) − logprob(我们的选择)`。

| 规则 | 条件 | 判定 |
|---|---|---|
| 1 | 我们的选择**不在**参考 top-10 | **结构性分歧**（变红之一） |
| 2 | 参考 argmax 概率 **p1 ≥ 0.90** | **结构性分歧**（变红之二） |
| 3 | 我们的选择在 top-10 **且** `Δlogit ≤ 1.0 nat` | **数值性 / 近并列翻转** |
| 4 | `Δlogit > 1.0` 或我们落在 r5 之后 | **非近并列**（既不许当噪声放过，也不许直接判"引擎有病"，另立条目查） |

**阈值取 1.0 nat 的理由**：`p1/p2 = e^Δ`，Δ = 1.0 ⇒ 首位只比次位高 **2.72 倍**，
这在"不同注意力核 / KV 口径 / 累加顺序都会翻转 argmax"的量级之内。

### 3.3 三个已知判定点（当标尺用）

| step | 参考 argmax | p1 | r2 | p2 | Δlogit | p1/p2 | 定性 |
|---|---|---|---|---|---|---|---|
| 1 | 21 | 0.70861 | 18 | 0.06823 | 2.3404 | 10.4 | **悬殊** |
| **7** | **21** | **0.38491** | **9167** | **0.27822** | **0.3246** | **1.38** | **近并列** |
| 16 | 198 | 0.50456 | 271 | 0.47238 | 0.0659 | 1.068 | 极近并列 |

### 3.4 本机实测的首分岔

| 配置 | 首分岔 | 我们的选择 | 参考同步 argmax | Δlogit | 判定 |
|---|---|---|---|---|---|
| 新 profile + 24568（流式档） | **index 7** | `9167`（参考 **rank 2**） | `21` | **0.3246 nat** | 规则 3 命中 ⇒ **数值性** |
| 1500（专家常驻档） | **index 15** | `1174` | `8` | — | — |
| 旧 `trace8` profile | index 16 | `271` | `198` | 0.0659 | 极近并列 |

- 规则 1 未触发（`9167` 在 top-10）；规则 2 未触发（`p1 = 0.385 ≪ 0.90`）；规则 3 命中。
- **`9167` 是真实竞争者，不是乱码 token**：同一参考探针里 step 1 rank 3（p=0.0609）、step 4 rank 4（p=0.0383）、
  **step 10 rank 1（p=0.1461 —— 参考自己在那里就选了它）** ⇒ 我们与参考在"**候选集合**"上一致，只在同一步的排序上不同。
- **⇒ 口径要求**：2003-id 上"与参考逐位相同"**只能声明到第一个近并列点之前**；
  本口径的硬锚是 **前 7 个 token（index 0–6）**。

### 3.5 档位与保真度（反直觉，但已实测）

| 配置 | 首分岔 index |
|---|---|
| 专家**走 CPU 池**（reserve 24568） | 7 / 15 |
| 专家**全常驻显存**（reserve 1500） | **15** |
| MTP 窗 2 | **15** |
| MTP 窗 4 | **20** |

⇒ 同一 profile 下，**专家住在 GPU 还是走 CPU 池，决定了近并列点在第几位被翻转**。
⚠️ 但这**不构成"更正确"的证明**（同 GPU 上的舍入 vs CPU 池的舍入本就会扰动量值）——
只能写成"换档后数值路径改变，且与参考逐位相同的长度反而变长"。

### 3.6 未验

- `9167` 的**精确 rank 与 prob 上界**（k=10 只给"在 top-10 内"；更大 k 需重跑一次 2003-id 采样臂，**未跑**）。
- 分岔点两侧 logits 的**逐位对照**（需要 `--dump-logits` 臂，**未跑**）。

## §4 已修的两处数值缺陷

### 4.1 缺陷一：GDN z 闸门 sigmoid → SiLU

| 项 | 内容 |
|---|---|
| **病** | GDN（30/40 层）输出端的 z 闸门，参考实现用 **SiLU**，本引擎用了 **sigmoid** |
| **症状** | 首位 token `107461`（"整"）；32 token 文本 = `整是inatom.manNEnenenene…` |
| **改法** | 改 **5 处 kernel + 1 处注释**，一次编译（见本文档 `09-fork-changelog.md` §1.1） |
| **改后** | 首位 token `514`（= ` int`）；32 token 文本与参考 **逐字符相同（88/88）** |

| 判据 | 改前 | 改后 |
|---|---|---|
| 首位 token | `107461` | **`514`**（与参考逐字节一致） |
| 32 token 文本（字节级 BPE 解码） | `整是inatom.manNEnenenene…` | **与参考 `content` 逐字符相同（88/88）** |
| `785` 死循环 | 位置 5–8 四连（仪器臂终点 8–11 连） | **0 次**，最长连续重复 = 1 |
| 与参考 logits 的 cos（raw / 去均值） | −0.5124 / −0.0931 | **+0.999658522 / +0.999143362** |
| 参考 top-8 在引擎里的秩 | 246023 / 186371 / … | **1 2 3 4 5 6 7 8**（同 id 同序） |
| Spearman（248,320 维） | −0.0736 | **+0.9987** |
| **回滚负控**（换回旧 exe） | — | **逐字退回 `107461 161431 76 20378`**，cos 到小数第 9 位复现 |

**定位方法链（真正值钱的部分）**：

1. 先证参考侧产物是真品（`cos(head(row_k), 参考 logits)` + 置换检验 **p = 0.002** + 负控能变红：打乱行序 0.99999 → 0.6824）。
2. 位置对齐零 GPU 钉死（`ladder(0,half0) == token_embd[ids16[k]]`，`max|d| = 0`）。
3. 权重 / 头部先判清白（630 张量、不一致 0；head 实为 **Q8_0**）⇒ 嫌疑压到"计算与调度"。
4. 把参考写成可执行规格，逐层对引擎阶梯 ⇒ 首次分歧锁定在**第 0 层 half1**；用**一个激活函数**把两个 oracle 干净分开。
5. 让"第一个生成 token 的 logits"可对拍（`STRATA_DUMP_FIRST_LOGITS=<path>` → 裸 f32 × 248320 = **993,280 B**）⇒ 从"逐块 cos = 1.0 的自洽假绿"变成"cos = −0.51"的**可判死**读数。**仪器自证**：dump 的 argmax 必须等于引擎自己的首位 token。
6. 每次起跑写 exe sha 并在跑前比对；**负控 = 换回旧二进制必须逐字退回**。

**15 位置 / 全层验证（规格侧，`A` 级）**：

| 判据 | 读数 |
|---|---|
| A（silu 读法 vs 参考） | **15/15 PASS**（全 ≥0.99，最小 cos = **0.992166 @ k=2**） |
| A 的负控（sigmoid 读法） | **15/15 全红**（min −0.0281），且 **k=14 的 argmax = `785`** ← 就是那个"未解释的死循环 token" |
| B（sigmoid 变体 vs 引擎阶梯） | **无一格掉下来**：9 格在 0.99715–0.99888，全在 k≥2 的深层（L19/38/39），最差 **0.99715 @ (k=11, L39)**；同批格在 silu 读法下是 −0.56…−0.02 ⇒ **分离度干净** |
| 副产物 | sigmoid 变体连**全注意力层**（真 RoPE + 多 key 因果 + GQA）都对上引擎阶梯 ⇒ **引擎的 RoPE / 掩码 / GQA 与参考一致** |
| 剩余 | **0.3% 数值残差未判别**（候选 = 专家重压 / 引擎 KV fp16）；**MTP 块（blk.40）未覆盖** |

**教训**：**引擎源码注释与它自带的 parity 测试都不是事实来源**（`gdn_parity` 拿引擎自己的 ref 当基准 ⇒ 自己对自己永远通过）；**日志会撒谎**（`native Q5_K head` 是硬编码文案，字节数 540,344,320 恰为 Q8_0，**只有字节数可信**）。

### 4.2 缺陷二：MTP 草稿放置 off-by-one

| 项 | 内容 |
|---|---|
| **病** | 验证窗口消费 `drafts[1..T-1]`（`drafts[0]` 预测的是已采样出来的那个 token，会被丢掉），而草稿侧写进窗口时用了 `drafts[i-1]` ⇒ **错位一格** |
| **改法** | `src/program/generate.cpp` 的 `use_mtp` 分支由 `drafts[i-1]` → **`drafts[i]`**；配套 `src/core/mtp.cpp` 的 `max_steps = std::min(max_t_, max_drafts_)`（草稿器要产 `max_t_` 跳，不是 `max_t_-1`） |
| **判据** | ① 接受率 **0.023 → 0.312（窗4）/ 0.632（窗2）**；新 profile 下 **0.550 / 0.583** ② 16-id prompt 上 `GOLD` 32/32 逐位相同 |
| **结论** | 修正**有效**，但**整体仍输**（decode 50.02 / 47.55 vs 同通道基线 55.14）⇒ **MTP 冻结（非判死）** |
| **机制换了地方** | ① 窗内多行验证开销（`pool` 7.5 → 12.0 / 24.9–26.3 ms/轮、CPU 专家 1.57 → 2.01 / 4.50 每层）② **草稿头吃 124–125 个槽**（`-> N slots` 1963 → 1839 / 1838） |

**为什么"有效但仍输"要分开写**：接受率上去了说明**修的是真缺陷**；decode 仍输说明**瓶颈换了地方**。
两者必须分开记，否则后来者会重做一遍。

### 4.3 附带修好的第三处：EOS 默认停机

| 项 | 内容 |
|---|---|
| **病** | `stop_eos` 默认 `false` ⇒ 引擎**无视模型自己的收尾信号**；且 `src` 里 `tokenizer.ggml.` **零命中** ⇒ 引擎**从不读模型的 `eos_token_id`**，只用硬编码集合 `{248044, 248046}` |
| **改法** | 默认 → **`true`**（与 `--serve` 路径一致）；新增 **`--no-stop-eos`**（raw 续写 + 负控）；注释写明本模型 `eos_token_id = 248046` |
| **判据** | 默认臂 **496 token（< 600）**、末 token = **`248046` = EOS**、` *{content}*` 复读 **0 次**；`--no-stop-eos` 负控 **600 跑满**、旧行为完整复现 |

⚠️ 引擎**不打印** finish/stop 行 ⇒ "停机"由 **token 数 < `--max-new`** ＋ **末 token = 248046** ＋
**结尾无后续生成** 三条合起来判定。要变成日志自证需再加一次引擎改动（**未做**）。

## §5 问答能力抽测

10 题（同一串 id、贪心）：**10/10 全对**，且**参考给出同样答案**：
①北京 ②春夏秋冬 ③100 °C ④约 3×10⁸ m/s ⑤180° ⑥面积 40 cm²、周长 26 cm ⑦2187 ⑧5050 ⑨180.8 元 ⑩24 人。

**"复读"的定性**：单题臂会复读"问…答…"脚手架，**但参考在完全相同的 ids 上也复读同样的脚手架**
（前 300 字符与引擎逐字相同）⇒ **复读 = prompt 无模板 / 无 stop 的格式问题，不是引擎故障**。

**一处先前的错判（留指针）**：曾判"这些臂没加 BOS"。**错**：`13` 不是 BOS 而是 **`.`**；
本模型 `bos_token_id = 248044`、`add_bos_token = False`。16-id prompt 首位是 13 是因为**prompt 文本本身**以 `.` 开头。
